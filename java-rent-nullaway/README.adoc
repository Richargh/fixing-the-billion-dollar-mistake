= Fixing the Billion Dollar Mistake in Java with NullAway

== Tech Stack

* link:http://errorprone.info/[ErrorProne]
** ⚠ ErrorProne requires link:https://errorprone.info/docs/installation[a couple of compiler args to work].
They are configured in link:.mvn/jvm.config[]
* link:https://github.com/uber/NullAway[NullAway]
** NullAway assumes that the absence of a `@Nullable` annotation means the type is non-null.
** NullAway respects multiple `@Nullable` annotations, including custom ones.
The name just has to be "Nullable".
(This repo used a custom annotation before March 22nd, commit 620710e93743f3067a3e6632e4c3ac141aec9023)
* link:https://jspecify.dev/[JSpecify] Annotations
** link:https://jcp.org/en/jsr/detail?id=305[JSR-305] has been dormant since 2012
** JSpecify is finalized and has a lot of industry backing
* Jackson
** Jackson does not validate fields.
Unfortunately that includes validating @Nullable annotations.
* Hibernate-Validation
** Used to validate `@Nullable` fields and that null fields not annotated throw exceptions.
** We need a custom `@Nullable` annotation that has runtime retention (which link:https://jspecify.dev/[JSpecify] has) and have to add a link:src/main/java/de/richargh/billiondollar/commons/json/external/DefaultIsNonNullableValidator.java[`DefaultIsNonNullableValidator`] so that null-deserialization without `@Nullable` annotation throws an exception.
* link:https://mapstruct.org/[MapStruct]
** Not used because the generated mappers cause nullaway to throw errors.
See link:https://github.com/Richargh/mapstruct-nullaway-mvn-java-limitation[MapStruct-Nullaway-Limitation] for more.
* Junit 5
